# Rules traceability — docs/RULEBOOK.md

Each rule in [RULEBOOK.md](RULEBOOK.md) is listed with where it is implemented and which automated test proves it.
Test names are quoted exactly from the test files (`describe › it`). Browser journeys in `e2e/` are Playwright
scripts, not part of the vitest suite; they are named as supporting evidence only and never counted as "tested".

**Status values**

* **tested** — a vitest test asserts the rule.
* **partly tested** — a test covers part of the rule; the uncovered part is named.
* **implemented, untested** — the code does it; no unit test asserts it.
* **discrepancy** — the code and a document (or the code and its own player-facing text) disagree. The rulebook
  follows the code. All discrepancies are collected in the last section.

Line numbers refer to the working tree at the time of writing.

### Review of the current-behaviour discrepancies (D1–D4, D8–D10)

Each was decided as **intended** (documented behaviour; the official rulebook already says what the code does, or the
code's own design depends on it) or as an **implementation defect** (code disagrees with the rulebook and with its own
player-facing text, and nothing depends on the wrong behaviour). Only defects were changed; no official rule was
changed and no ratings math was touched.
