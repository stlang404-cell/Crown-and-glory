# Dependency-gated implementation plan

No milestone is complete because TypeScript compiles. Each requires an actual playable build, automated domain evidence, persistence validation and interface verification, with limitations recorded. Preserve all existing full-system scope. Advanced economy/dynasty cannot bypass M1/M2.

| Gate | Required implementation | Concrete acceptance |
| --- | --- | --- |
| M0 Foundation/rules | TS/Vite/React skeleton, exact variant schema/rules/notation, deterministic tests, dependency/license manifest | Legal board playable locally; promotion/check/mate/stalemate/draw/timeout policies complete; independent oracle/perft checks; no stub legal moves. |
| M1 Engine/matches/ratings/persistence | Pinned real local engine, workers, calibrated baseline opponents, clocks, full game records/Library, Glicko-2, rating history, portable export/import; initial versioned move report and report persistence | Finish rated6×6 game, restart and replay every position, inspect actual best continuations/justified experimental grades, explain rating delta and compare available history. Cancel analysis responsively. No fictional numbers. |
| M2 Analysis/intelligence/coach/training | Full calibrated/versioned grades/accuracy and phase stats, critical positions, interactive alternatives, ten-skill profile, archive filters/bookmarks, held-out assessments, coach, targeted retries/effectiveness, career trends |100-game fixture history supports meaningful filtered comparisons and sourced weaknesses. Every move links exact engine evidence; incompatible methods never merge silently. Exceptional labels verified, absent evidence honest. Mobile analysis flow verified. |
| M3 Civilization/events/spectating | Persistent2048 identities, deterministic tick tiers, all league/tournament formats, qualification, rank history, rivalries, retirements/entrants, spectator boards | Seeded multi-season runs reproduce schedules/results; no duplicate pairing/settlement-source events; replayable games legal/full-recorded; abstract ones explicitly summary-only; promotion/relegation traceable. |
| M4 Exchange/economy/progression | Match/draw/tournament/promotion/qualification/season/conditional markets, forecasts, portfolio, NPC traders, reserves, ledger, clubs/facilities/sponsors/hosting, recovery | Math/rounding/conservation/portfolio reserve tests; replay/reset/conflict/void exploits tested; funded prizes; specialist/hybrid economy sensitivity study; no real money. Conditional claims use documented bounded state spaces. |
| M5 Polish/performance/offline/release | Original visual assets, accessibility, budgets, actual Windows launcher and iPhone PWA, migrations/backups, complete offline assets, license/source package | Real-device airplane-mode install/restart, suspend/resume, memory/thermal/load checks; quota and corrupted-save recovery; complete UX audit and signed evidence checklist; no completion on compilation alone. |

M1 includes minimum postgame reporting because the preserved mandatory expansion requires it; M2 completes calibration and lifetime development. This is an intentional overlap, not a decision to postpone core reporting to M4. M1 may use truthfully labeled experimental methodology, but final validated-analytics claims require calibration at M2. Engine before coach; durable history before graphs; legal replay before engine explanations; balanced ledger before markets; NPC event truth before settlement.

Estimated effort is not supplied as a false certainty. Claude must inspect the actual repository, identify reusable work and produce a scoped plan with resource estimates and remaining gates. If constraints prevent a gate, report the precise blocker and retain the requirement rather than substituting a static UI or hidden mock.
